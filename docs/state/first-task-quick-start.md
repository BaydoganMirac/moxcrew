## Owner direction

The owner requested a new feature, selected easier first use as the priority,
and explicitly approved Task0038 implementation on 2026-10-19.
[Task0038](../plans/0038-first-task-quick-start.md) makes the proposed slice

first task start through the existing native controls.

## Implemented

- Inspected current project/folder, provider-readiness and work-composer paths,
  plus the completed Task0028 and Task0036 onboarding work.
- Recorded the discontinuous setup path as repository evidence and the benefit
  of a continuous guide as an unverified usability hypothesis.
- Prepared owned files, interaction/failure behavior, acceptance and rollback.
- Added the nonmodal native guide, explicit project/folder selection, reused
  folder controls, provider diagnostics, draft-preserving task navigation and
  a return action from Tasks/Providers. Empty Projects offers the guide;
  populated owners are not redirected.
- Progress is derived from saved facts. Completion requires an applied start,
  its exact run and frozen project context, so queued, uncertain or foreign
  work does not fabricate completion. History checks use bounded linear passes.
- The guide requires the existing stable Codex0.155.1 memory-compatible minimum
  for project-bound work, while ordinary control capabilities are unchanged.
  Availability does not claim provider authentication.
- Added TR/EN text and seven behavior checks, including all stages at800x560
  in both languages/themes. All97 desktop checks pass, as do the unchanged
  core suites in the full workspace run. Strict all-target/all-feature Clippy
  passes. A sandboxed desktop retry initially denied existing loopback fixtures;
  the same tests pass with local-server permissions, without runtime changes.
- Added test-only disposable native scenes. Setup/queued facts use the real
  Host; task-scene readiness and failure feedback are explicit UI fixtures.
  No provider turn, owner setting/data or Cloud behavior changed.
